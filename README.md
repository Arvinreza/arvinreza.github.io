# Alexander Koplenig — Publications

Personal academic publication website: [https://koplenig.github.io](https://koplenig.github.io).

This repository contains a static, responsive publication list synchronized with the **public works** of ORCID [0000-0002-9630-9680](https://orcid.org/0000-0002-9630-9680). No database, paid hosting, JavaScript framework, or Python packages are required.

## Initial publication (GitHub Pages)

1. Open **Settings → Pages** in this repository.
2. Under **Build and deployment**, choose **GitHub Actions** as the source.
3. In **Actions**, open **Sync ORCID publications and deploy site** and click **Run workflow**, selecting `main`.
4. After the workflow succeeds, open **https://koplenig.github.io**.

The same workflow runs on pushes to `main` and every **Monday at 06:13 UTC**. The first run fetches the works from ORCID and enriches DOI records with bibliographic metadata from Crossref. Scheduled runs may occasionally be delayed by GitHub.

## What is imported?

- Public ORCID works are the source of truth for *which works are included*.
- Where available, Crossref adds author lists, journal, volume, issue and pages.
- Works without DOI are included using their available ORCID metadata.
- Duplicate DOIs and normalized titles are deduplicated.
- Records are displayed newest first and can be searched by title, authors and venue and filtered by year and type.
- Works marked private or visible only to trusted parties in ORCID are **not** imported.

To complete your publication list, ensure your ORCID public record contains the relevant works. The initial `data/publications.json` file is empty by design and will be generated by the first successful import. Never replace it with sample or invented publications.

## Manual corrections and additions

Edit `data/manual_publications.json`. For example:

```json
[
  {
    "title": "Example title — replace before using",
    "year": 2026,
    "type_label": "Preprint",
    "authors": ["Alexander Koplenig"],
    "venue": "Preprint server",
    "doi": "10.1234/example"
  }
]
```

**The example above is documentation only**, not live data. A manual entry with an existing DOI or equivalent normalized title overrides the corresponding ORCID record's supplied fields. Additional entries are included as new records.

## Connectivity and error handling

ORCID endpoint: `https://pub.orcid.org/v3.0/0000-0002-9630-9680/works`.

This site first tries the unauthenticated public API. If the service requires a token, register an [ORCID Public API client](https://info.orcid.org/documentation/integration-guide/registering-a-public-api-client/), obtain a `/read-public` OAuth token and save **only the token** in the repository's **Settings → Secrets and variables → Actions → New repository secret** under the name `ORCID_ACCESS_TOKEN`.

For Crossref, you may optionally set `CROSSREF_MAILTO` as a repository **Actions variable**. Never commit private credentials.

Transient ORCID errors retain a previously saved *nonempty* publication snapshot. If no valid snapshot exists, the import and deployment fail rather than silently publishing an empty bibliography. Missing Crossref metadata never causes ORCID works to disappear.

## Local development

Run from the repository root:

```sh
python3 scripts/fetch_orcid.py
python3 -m unittest discover -s tests -v
python3 -m http.server 8000
```

Open http://localhost:8000. To omit Crossref while testing, use `python3 scripts/fetch_orcid.py --no-crossref`.

## Structure

- `index.html`: homepage structure and introductory copy
- `assets/style.css`: mobile-responsive styling
- `assets/site.js`: client-side publication rendering and filters
- `scripts/fetch_orcid.py`: ORCID + Crossref import
- `data/manual_publications.json`: optional hand-edited corrections
- `data/publications.json`: generated works snapshot
- `.github/workflows/sync-publications.yml`: automatic synchronization and Pages deployment
- `tests/`: importer unit tests

No tracking or third-party JavaScript is used. All displayed bibliography text is inserted as text, not HTML.
